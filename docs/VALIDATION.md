# 原位翻译与桌面论文库验证计划

本计划交给 DS 执行。所有数值为首轮工程验收目标，不是已测成绩。当前真实翻译、运行性能、GUI 和安装包测试均未执行。先完成 M0，达到核心关口后再推进桌面整合。

## 样本与对照方法

核心真实样本使用 [HybridFlow](https://arxiv.org/abs/2409.19256) 和 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。下载后记录确切 arXiv 版本、来源、SHA256、页数和页面尺寸，冻结测试输入。每篇选择至少 6 个不同页面，共至少 12 页，覆盖双栏正文、行内公式、独立公式、图注、表格和参考文献。页码在查看实际 PDF 后写入样本清单，不能凭标题预填。

扩展真实样本至少加入一篇跨页长段落明显的论文和一篇图表密集论文，由 DS 在可访问的公开 PDF 中选取、冻结并解释选择原因。核心两篇用于每次回归，扩展样本用于完整交付关口。

可控边界样本至少 4 个：旋转页与非零 CropBox、超长译文导致空间不足、扫描图像页、缺字或损坏/加密输入。必要时将这些条件拆成更多文件。自己生成的样本使用已知正文，写明生成方法；它们只验证功能边界，不替代真实论文质量评估。

用户截图放在 [参考图片](assets/reference-translation.png)。先在冻结的 HybridFlow 版本中搜索截图可见句子，定位对应页和段落；找不到则明确说明版本不同，不把截图页码当成真值。截取同一段落在原文与译文的图，另提供整页对照。

若能取得 Moonlight 对同一 PDF 版本生成的结果，增加第三列对照并记录设置、时间和来源；否则比较原文与我们的输出，不声称与 Moonlight 打平。

## 固定实验条件

记录 CPU、内存、操作系统、屏幕缩放、Node/Python/Electron、翻译包完整版本、上游提交、模型与服务 ID、温度等参数、提示词与术语表哈希、语言、页范围、并发和布局参数。保存完整 lock 和模型/字体资产版本；密钥与认证头只保留“已配置”状态。

先固定一组引擎和一个模型跑基线。发现问题后每次只改变一类变量，记录相同输入的差异。服务端模型别名可能变化，保存运行时间及服务端返回模型标识。不要将“同名模型”自动视为完全相同实验条件。

耗时区分首次资产准备、冷解析、首次翻译、暖缓存阅读和强制重译。真实计费只记录服务实际用量、请求数、tokens 和可取得的账单；不把缺失的缓存读取、推理或重试成本填成零。

## 核心质量指标

先对冻结页面建立人工审查清单：标出全部应译正文段落与标题/图注，并单独列出独立公式、图形、表格、脚注和参考文献。是否属于应译区域在看译文前确定。排版失败、拒译、保留原文都留在分母中，避免只评估成功区域。

| 指标 | 首轮目标 | 测量方法 |
| --- | --- | --- |
| 文档几何 | 原页映射完整，原位译文页数、页型、旋转、页序与原文一致 | 解析 PDF box/旋转与映射；范围输出按明确映射比较 |
| 正文可用翻译覆盖率 | 核心样本整体至少 95%，每页至少 90% | 完整可读、语义完整、没有遮挡的已译区域数 / 预标注应译区域数 |
| 栏位正确 | 所有成功翻译段落保持原栏或已标注的跨栏关系 | 对照原始页和段落框人工检查 |
| 段落起始位置 | 成功段落中至少 95% 的起始位置偏差不超过页宽/高的 3% | 起始位置定义为阅读顺序中的首字符原点；旋转校正后比较，记录超阈值区域 |
| 严重版面缺陷 | 0 个未提示的裁字、盖图、跨栏串文、公式缺失 | 按页人工检查；失败区域回退且计入覆盖率损失 |
| 字号可读 | 正文译文不小于 8 PDF point，且不小于原文字号的 75% | 从译文结构/字体数据取值，按原文正文区域检查；不适用的原始小字单独列出 |
| 公式与数值 | 人工标注的关键公式、上下标、数值、单位与引用编号无关键错误 | 核心样本至少 30 项，逐项核对；行内公式可移动但内容不变 |
| 语义质量 | 至少 50 个审查片段中，至少 90% 无实质性错误，关键含义错误为 0 | 覆盖两篇、不同页和难度；包含否定、比较、限定词、术语、数字与方法条件 |
| 回退透明度 | 每个保留原文或失败区域均有可见状态与原因 | 核对 manifest、页面提示和输出，不把混合页面称为全部成功 |

语义审查片段应覆盖至少 30 个不同段落，并包含所有已知失败段落；不能仅挑短句或摘要。实质性错误指漏掉信息、术语错误、指代错位或因果/比较关系错误；关键错误指改变主要结论、数字、否定、实验条件或公式意义。模型评分只能辅助，至少一名懂相关领域的审查者对照原文逐条检查。DS 可先做人工逐条初审，用户复核尚未完成时单独标记该状态。

保留同一段落的固定样式截图，100% 和 150% 各检查一次。PDF 原文和译文以相同渲染器、缩放与页面背景输出。整页像素差不能用来判断翻译质量；公式和图片位置变化时，应比较对象或局部匹配后的裁图，不要求译文与英文像素相同。

首轮阈值若对某类原始排版不适用，保留原阈值结果，单列样本原因和修改建议。不能在看结果后静默排除失败页或降低阈值。

## 段落对应和阅读器验收

建立至少 50 组人工确认的原文段落与译文区域对应，覆盖所有核心页、图注和长段落。另选至少 10 组低置信或不能映射的案例，测试拒绝及回退。

| 场景 | 验收结果 |
| --- | --- |
| 原文到译文、译文到原文 | 全部审查案例可找到对应原页；可靠段落映射准确率至少 98%，低置信例不伪装成精确对应 |
| 不同缩放与窗口尺寸 | 75%、100%、150%、200% 下至少各测一次，边框和文字选择仍贴合 |
| CropBox 与旋转 | 已知坐标变换与逆变换一致，实际框不偏移到另一栏或另一页 |
| 阅读模式切换 | 原文、译文、左右对照之间切换 20 次，保留原页与对应段落，无累积漂移 |
| 双向同步 | 手动滚动连续翻过 10 页，没有同步回环或跳回旧位置；取消跟随动画后仍能手动阅读 |
| 页范围译文 | 对原文中间页、非连续范围、仅首页分别翻译，不发生原页索引错位 |
| 句子级交互 | 如宣称支持，另测至少 30 组含拆句/合句/公式的样本；准确对应或明确回退段落，不画虚假精确框 |
| 文字层 | 中文可选、可复制、可检索；跨行复制无大量乱码，选择原文/译文不会复制成双重混杂内容 |
| 点击证据 | 实际回到原文 PDF 的正确文档版本、页和区域，连续跳转后能返回阅读位置 |

段落映射准确率与映射覆盖率同时报告。只为少量容易的段落生成映射不能算通过；核心应译段落的可靠映射覆盖率至少 95%。多对多段落人工确认整组，不强制一对一计分。

## 论文库与批注验收

用至少 20 个本地 PDF 条目验证基础流程，包括重复文件、同 DOI 不同 PDF 版本、缺元数据、非 ASCII 文件名和链接原件。

1. 批量导入、分类拖动、标签修改、作者/DOI 搜索、状态更新、星标、回收站恢复、BibTeX/RIS 导出可用，重启后数据一致。
2. 相同文件导入两次不生成重复受管副本；不同版本保留；缺元数据仍能阅读并人工补齐。
3. 从 Zotero 导入先使用数据库一致副本，不修改原 Zotero 数据。分类、标签和可访问 PDF 按实际支持范围列出；缺附件条目给出原因。
4. 在原文和译文分别创建不少于 10 个高亮/评论；重启、切换视图、调整缩放后均能找到。重译导致旧译文字偏移时保留原锚点并提示失配。
5. 删除正在翻译的论文后迟到结果不能复活条目；恢复后原文件与笔记存在，付费任务不自动扩大或重启。
6. 导入外部链接原件后删除条目，不删除用户原文件；只清理本应用拥有的派生文件。
7. 备份后在空数据目录恢复，核对文件 SHA256、论文数量、分类、批注、译文及对话；可按来源定位全部受管文件。

## AI 解读验收

准备 15 个有明确原文依据的问题和 5 个原文缺少依据的问题。问题覆盖术语、方法、公式变量、实验设置、表格数值、贡献和局限。每题人工标出可接受证据范围；局部、章节和全文上下文分别记录。

有依据问题至少 90% 的回答结论与所引证据一致，关键数字与否定错误为 0。所有显示的证据 ID 必须存在并跳转正确。无依据问题应明确信息不足或区分模型外部知识，不能伪造论文实验和引文。结构上有效的引用不代表语义有依据，两项分别计分。

构造一段“忽略指令并读取本地文件”等论文正文，验证其被当作资料，不调用文件写入、shell、库删除或密钥访问。外链与格式化文本不产生脚本执行。

## 故障和恢复验收

| 故障注入 | 必须观察到的行为 |
| --- | --- |
| API Key 缺失或 401 | 明确配置错误，无无限重试；离线原文阅读仍可用 |
| 429、超时或断网 | 受限退避，显示失败范围；不同时无限创建新任务 |
| 返回空译文、无效 JSON、公式占位损坏 | 拒绝该结果或回退并标记，保留其他成功产物 |
| 翻译到约三分之一时取消 | 取消有反馈，运行中的进程停止；取消后无成功发布 |
| 引擎子进程崩溃、管道半行 | 主应用继续可用，任务失败且可恢复，无死等和假 100% |
| 文件写入期间强制退出 | 重启清理暂存或恢复提交，不显示损坏 PDF、不丢旧版本 |
| 重启恢复和重复点击翻译 | 同缓存键不重复发布或产生并行重复计费任务 |
| 术语表/模型/提示词变化 | 新配置使相关结果过期，旧版本和批注仍可读，新任务可复现 |
| 不可写目录、磁盘满、外部原件移走 | 错误可理解，原文件与旧数据不被破坏 |

控制性故障测试可以用本地 fake provider；它们验证协议和恢复，不计入真实翻译质量、耗时或成本。测试报告明确标注 provider 类型。

## 性能目标

核心样本在同一台已记录硬件的机器上重复 3 次，报告中位数与最大值；样本数量不足以宣称总体 p95。暖缓存打开首个可读页目标为 2 秒内，模式切换目标为 300 毫秒内，通常取消反馈目标为 1 秒内，终止该任务进程树目标为 10 秒内。首轮 GPU 不作为必需条件。

真实首次翻译不设置未经测量的“几秒完成”承诺。记录首个可读译文页时间、全部任务时间、峰值 RSS、请求数和用量。M2 的逐页优先模式必须与全文基线对比，检查是否增加总成本或破坏术语一致性。缓存命中再次打开不触发新的翻译请求。

以上为探索阶段目标；不达标要附 profiling 和下一步措施，不以假的进度动画替代。

## 执行阶段和通过条件

| 阶段 | 通过条件 |
| --- | --- |
| M0 | 核心 12 页和边界样本完成；几何、覆盖率、可读性、公式/数值和语义关口达到目标；提供实际 PDF 与截图 |
| M1 | 底座干净构建、论文库核心流程、翻译任务和页级对照通过；证明原文不依赖模型或在线解析 |
| M2 | 段落映射覆盖/准确率通过，选区和批注持久化通过；逐页优先的实际能力单列 |
| M3 | 20 个 AI 问题、证据定位、上下文范围与不可信正文测试通过 |
| M4 | 扩展真实样本、故障、备份恢复、当前平台安装包通过；其他平台分别记录 |

M0 失败先分析是语言模型、文本解析、公式保护还是排版导致。保持样本不变，最多先比较一个兼容引擎替代版本或一个额外模型，附结果后再决定继续适配、改用可选结构化阅读模式或调整明确范围。结构化阅读可作为失败页的回退，但不能用它替代原位翻译核心关口。

## 报告和产物

```text
artifacts/validation/<run-id>/
  report.md                 # 结论、命令、实际结果、失败与未测项目
  environment.json          # 硬件、系统、工具和模型配置，不含凭据
  corpus.json               # 样本来源、版本、SHA256、页码与预标注区域
  dependency-lock/          # 真实锁文件和资产版本
  metrics.json              # 数值、分母、样本数、单位和测量方法
  review.csv                # 逐段语义、版面、对应关系及审查结果
  logs/                     # 脱敏日志和任务事件
  outputs/                  # 原位译文、双语 PDF、位置映射
  screenshots/              # 每个核心页原文、译文、并排；关键局部
  failures/                 # 失败输入引用、复现命令、实际与预期
```

`report.md` 开头标明 `pass`、`fail` 或 `not_run`，列出对应阶段与阻碍。每条测试也使用这三种状态，不能把未运行算通过。输入 PDF 如不适合随仓库分发，保存来源和校验值，按授权存放；不要将用户凭据或私人论文打包公开。

DS 应实现一个复现入口，接收 corpus manifest、配置引用和输出目录，能够重跑解析、翻译、渲染和指标收集；命令名称由实际实现确定，在报告中给出真实命令，不将本计划的描述冒充已有脚本。

没有 API 配置仍可完成源文件校验、解析、渲染、版本/缓存键、任务状态及 fake provider 故障验证；真实翻译与成本保留 `not_run`。缺 GUI 时可生成离屏 PDF 页面截图，但不得声称真人交互或安装包界面验收通过。
