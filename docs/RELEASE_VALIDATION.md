# 可靠性、管理闭环与 Linux 预发布验收

日期：2026-11-01（北京时间）。本轮产物是 Linux x64 预发布包，不能据此宣称所有成熟度和跨平台目标已经通过。

## 产物和运行方式

- `release/Moonlight-0.1.0-linux-x64.tar.gz`：可解压运行的完整桌面包。
- 同名 `.sha256` 与 `release/manifest.json`：整包校验、Electron 版本与原生核心版本。
- 包内有官方 Electron、ASAR 中的应用与 PDF.js、Rust 核心、rclone。应用启动不依赖源码目录、Node.js、Cargo 或 Python。整篇 PDF 翻译仍需要另装 BabelDOC 及模型配置；Codex 需要官方 CLI 与人工登录。
- 在有 Electron 系统依赖及 Chromium 沙箱支持的 Linux 桌面解压，运行 `Moonlight-linux-x64/moonlight`。升级前退出旧应用，备份论文库，再替换程序目录；用户数据与程序目录分开保存。
- 当前包未签名，无自动更新服务，也没有 Windows/macOS 安装包。默认启动不会添加 `--no-sandbox`。

使用官方 [Electron Packager](https://electron.github.io/packager/main/) 打包；ASAR 与原生额外资源遵循 [Electron 分发方式](https://www.electronjs.org/docs/latest/tutorial/application-distribution)。构建目录采用显式文件清单，不复制论文库、开发依赖、凭据或 `.venv`。新增打包依赖引入的 glob/minimatch 公告已通过锁定修复版本处理，本轮 npm audit 为零；未把这一结果扩展为 Rust/Python 全依赖安全审计。

## 数据与任务可靠性

| 原问题 | 修复与验收 |
|---|---|
| 导入元数据先提交，正文索引失败后留下半成品 | 元数据、版本与正文索引在同一事务内提交；注入索引写失败后重新导入成功 |
| 删除数据库失败，但关联 PDF 已删 | 先提交数据库删除，再清理无共享引用的托管附件；注入删除失败后原文件仍在 |
| 回收站中的论文继续发布译文 | 移入回收站取消任务；发布事务检查论文仍有效、任务未取消 |
| 取消已完成任务把状态改成 cancelling | 终态不回退；取消已完成任务保持 completed |
| 引擎生成任意文件仍算成功 | 检查 PDF 可解析且页数大于零；无效 PDF 标记失败，无译文版本 |
| 应用崩溃后永远显示翻译中 | 启动恢复中断任务为 failed，并说明原因；任务中心可重试 |
| 状态提交失败仍出现成功译文 | 译文版本、论文更新时间、任务完成状态同事务提交；注入完成写失败，无译文版本 |
| 无界并发和重复任务 | 单个翻译工作线程、32 个等待任务，同一论文最多一个活动任务；排队取消不启动引擎 |
| 两个应用同时接管任务 | 应用单实例锁与原生论文库独占文件锁；第二个核心无法打开同一库 |
| 关闭窗口留下任务 | 正常退出先取消任务并等待核心退出；Linux 引擎设置父进程死亡信号。未声称已验证所有引擎子孙进程的强杀回收或断电恢复 |

清理附件失败时可能保留无引用文件，接口返回 retained_files；当前没有自动垃圾回收，不会为释放空间冒险删除仍被引用的文件。

完整备份使用 SQLite 官方在线备份 API，包含数据库、托管原文/译文、Zotero 附件与迁移归档。已关联的外部 PDF 会复制进备份并改为可迁移相对路径，恢复后不依赖原外部 PDF。每个备份文件附带 SHA-256；恢复校验清单、路径、数据库完整性、外键和引用附件，并执行正常升级迁移。恢复总是在新目录，失败清理临时目录，旧库保持可用。登录和云同步密码不进入备份。链接式 HTML 的外部站点资源不属于已托管附件，不保证离线网页完整性。

## 管理与 AI 闭环

- 论文列表和阅读器均可编辑标题、作者、年份、期刊/会议、DOI、arXiv、摘要、阅读状态与笔记。
- 支持分类多选、新建分类、标签编辑；资料和分类标签在同一事务提交。过期编辑版本被拒绝，避免覆盖已经保存的修改。
- 全局任务中心显示最近 100 个翻译任务，支持打开论文、停止和失败重试；关闭阅读器后仍能找到任务，完成时刷新论文库。
- AI 回答可以追加到论文笔记并导出 Markdown，附上原文片段和页码；本地历史保留，重启恢复。
- 页总结不再固定截断前 20 个块，统一使用最多 32,000 字上下文；超出上限会提示。
- 文档检索在 SQLite 内对该原文版本的所有正文块评分，不再丢弃第 1200 个块之后的证据。
- 超范围引用号会明确警告，历史回答也会重算警告。警告不等于证明回答正确，也不会把无效引用擅自改成有效引用。

## 实际验证范围

机器可读证据目录为 `artifacts/validation/release-20261101/`。

- `project-checks.json`：统一回归入口，覆盖 Rust、React、Node、生产构建、真实 PDF、导入响应性、Zotero、可靠性、故障注入、AI 检索和云传输。故障复现现已作为失败即退出的 CI 门槛。
- `faults.json`：6 个原审计故障均通过明确验收断言。
- `ai-context.json`：60 块页面尾部进入上下文；第 1300 块的相关证据被检索；无效引用 `[999]` 被提示。
- `packaged.json`、`packaged-reader.png`：先验证整包哈希，解压到源码目录以外的临时目录，再从解压出的真实程序启动。7 项流程包括首次启动、资料/分类/标签/笔记编辑、AI 保存与导出、引擎失败后重试、旧 annotations/FTS 结构升级且保留数据、完整备份、恢复到新库并重启。页面异常为零。
- 升级测试使用构造的旧数据库结构，并非运行两个历史版本安装器；恢复测试由应用正常退出，再由测试工具重新启动同一可执行文件，以免额外启动的进程逃离测试控制。
- `package-integrity.json`：发布包 UI 与本地构建一致、原生核心哈希一致、rclone 一致，ASAR 无论文库和凭据。
- 原有 Codex 桌面协议回归也通过，模型与网页登录完成仍使用模拟协议。本轮线上账号登录、模型质量和真实云供应商账号未重测，也没有向线上模型发送论文正文。
- Electron 在虚拟显示中测试；测试工具为此容器添加了 OS 沙箱禁用参数。真实桌面 GPU、系统沙箱、系统密钥环、断电恢复和操作系统安装器生命周期没有因此被证明通过。

## 万篇性能复测

复用此前导入的 10,000 个有效 PDF、401,378 个正文块、10,000 个批注；其中大部分是控制生成样本，不是万篇独立真实论文。此次结果只覆盖 Rust JSONL/SQLite，不替代 Electron 整机性能测试，且未清空系统文件缓存。

| 项目 | P95 |
|---|---:|
| 首屏列表 | 4.11ms |
| 标题排序 | 4.69ms |
| 年份排序 | 4.30ms |
| 稀有正文检索 | 2.25ms |
| 保存笔记 | 7.84ms |
| 高命中率正文检索 | **463.31ms，未达 200ms 目标** |
| 短查询 | 317.94ms |

核心及解析辅助进程 RSS 在长序列操作前后均约 47.95MiB，数据库完整性检查通过，无协议错误。完整结果为 `scale-10k.json`。高命中率全文查询仍是明确性能阻塞项，门槛没有为此放宽。

## 复现

```sh
# Node 22.12+、Rust、Python 验证依赖与 rclone 准备好后
.venv/bin/python scripts/validate_project.py --report artifacts/validation/release-20261101/project-checks.json
npm --prefix app run package:linux
# Linux 图形会话及 Electron 运行库已准备好时
node app/e2e/release.mjs
# 万篇样本已导入后复测，--enforce 会因现存全文检索超标退出失败
.venv/bin/python scripts/benchmark_library.py --work-dir /tmp/moonlight-scale-10k --reuse --enforce
```
