# 云同步（2026-11-01）

设置入口：**设置与状态 → 云同步**。支持七牛云 Kodo、阿里云 OSS、坚果云/通用 WebDAV 和其他 S3 兼容存储。传输直接复用开源 [rclone](https://rclone.org/)，本轮安装版本 `v1.75.2`，官方压缩包 SHA256 记录在 `tools/rclone/SOURCE.json`。

本机已完成协议测试；未连接真实云账号，桌面 GUI 和操作系统密钥服务的实机验收尚未执行。

## 配置

| 服务 | 地址示例 | 其他配置 |
| --- | --- | --- |
| 坚果云 | `https://dav.jianguoyun.com/dav/` | 账号邮箱、第三方应用密码；默认同步文件夹 `Moonlight`。 |
| 七牛 Kodo | `https://s3.cn-east-1.qiniucs.com` | 对应地域、S3 空间名、AccessKey、SecretKey；按实际地域替换域名。 |
| 阿里云 OSS | `https://oss-cn-hangzhou.aliyuncs.com` | 已存在的 Bucket、对应区域、AccessKey ID 和 Secret；使用 OSS API 地址。 |
| 其他 S3 | 服务商的 S3 Endpoint | Bucket、Region、AccessKey、SecretKey，可选路径式桶地址。 |

七牛的 S3 空间名可能不同于普通空间名，以控制台为准。[七牛官方 S3 域名说明](https://developer.qiniu.com/kodo/4088/s3-access-domainname)。阿里云等供应商参数交给 [rclone S3 后端](https://rclone.org/s3/)处理。坚果云应用密码和访问限制见[官方帮助](https://help.jianguoyun.com/?p=2064)，通用协议参数见 [rclone WebDAV](https://rclone.org/webdav/)。

两台设备使用相同服务、存储桶和同步文件夹。先保存设置并测试连接，再执行“立即同步”；可开启应用运行时每 15 分钟同步。同步在后台执行，可取消，完成后刷新列表与打开的论文信息。

坚果云官方当前说明有单次目录列举 750 项、请求频率和单文件大小限制。程序将附件按哈希前两位分目录，提交按设备每 512 条分组，避免将全部记录平铺在一个目录；附件传输使用精确对象查询，不遍历整个远端附件树。坚果云默认保守限速每秒 0.2 次，可在界面调整。限速按本次传输进程生效，账户上的其他应用和其他设备仍共同占用服务商额度；大库首次同步耗时需要真实账号验证。该分组方式不是对无限历史记录规模的保证。

## 同步内容和行为

- 包含论文元数据、原文/译文版本、分类和标签关联、文字笔记、批注、AI 对话数据，以及已迁入的 Zotero 来源记录和本地附件。`files/`、`derived/`、`imports/` 下普通文件进入附件清单，包含迁移档案及网页资源。
- SQLite 数据库留在本地。以论文文档、分类、标签为单位同步结构化数据，使用一致的独立只读事务导出；不上传运行中的数据库、WAL、模型密钥、云凭据、缓存和临时目录。
- 独立字段或不同批注的修改自动三方合并。同字段修改、删除与编辑冲突保留两端数据，设置中展示本地/云端冲突内容，由用户选择后继续传播。
- PDF、附件按 SHA256 存入不可变对象；下载先校验再落盘。文件同一路径的并发修改也保留冲突，云端原对象留存。
- 元数据提交包含依赖关系，按因果顺序接收；每条提交具有内容哈希。附件先上传，元数据提交最后发布，避免把尚未上传的文件当成完成。
- 待发布提交留在本地 outbox，失败或重启后重试。恢复以对象/提交为单位，单个中断大文件可能重传，不保证跨进程按字节偏移续传。
- 永久删除通过论文删除记录传播，遇到对端新笔记/批注时先产生冲突。远端旧对象和历史提交暂不自动删除；需要后续历史压缩与垃圾回收。
- 外链文件先复制为本地管理的相对路径，解决另一台设备无法使用原绝对路径的问题；缺失外链会报告错误。外链 HTML 的外部依赖资源不保证自动收集，Zotero 已复制的网页资源目录可随库同步。
- 分类/标签定义当前采用增量保留；论文上的分类/标签添加和移除会同步。全局分类定义删除、复杂重命名与手动改库不作为本轮完整兼容保证。
- PDF 几何和全文索引为本地派生缓存，不同步 FTS 表；新设备阅读页面后由 PDF.js 建立几何索引。尚未实现下载后自动重建全库全文索引。

## 性能实现与证据

- SQLite 触发器记录变更文档和修订号；有改动时读取相关文档，大批变更才使用批量全表导出；无改动时跳过元数据导出。
- 首次或新目标需要全量元数据初始化；之后比较的基线仅限候选文档，不逐篇查询整个库。导出使用独立读取连接，合并按 50 条一批短事务写入。
- 文件哈希缓存由大小和修改时间判定。文件缓存、已有云端哈希和冲突集合批量读取，缓存更新按 100 条提交，避免扫描时逐文件读数据库；文件系统仍需检查本地文件。
- rclone 每次最多两路文件传输，处理认证、流式上传、重试和供应商差异。变化文件暂存为稳定副本，上传期间需要相应临时磁盘空间。
- `artifacts/validation/cloud-sync-20261101/report.json` 记录：单篇元数据修改的候选文档数为 1、附件上传数为 0；无改动同步的候选文档数、上传记录数和上传文件数均为 0。

这不是十万篇真实全文库同步的耗时/内存基准。历史提交目录还会随着使用增长，首次接入新设备仍需重放历史；历史压缩及大库真实云端压测属于后续工作。

## 凭据

Electron 主进程通过系统 `safeStorage` 保存加密配置，渲染器只拿不含密钥的配置摘要。没有可用系统密钥服务时仅保留本次会话凭据，不回退到明文存储。rclone 凭据通过子进程环境传递，不出现在命令行和同步文档中，原始服务商诊断不写入日志。凭据文件位于应用配置目录，外于论文库的同步目录。

云端内容使用 HTTPS 传输；本轮未实现客户端端到端加密。账号与存储端加密策略由服务商配置。只允许 HTTPS 服务，回环 HTTP 仅供本地协议测试。

测试使用真实 rclone 客户端、认证回环 WebDAV 服务和开源 Moto S3 模拟服务。覆盖七牛/阿里云/S3 配置的对象读写、两端往返、独立字段合并、笔记冲突、删除与新增批注冲突、损坏附件、后台响应与取消、上传失败后重启重试及后续编辑。

Node 测试覆盖凭据加密调用、渲染器脱敏、系统密钥服务不可用时不明文落盘、切换地址不沿用旧凭据；React 测试覆盖服务预设、配置和冲突选择。操作系统加密器在这些测试中是替身，未声称实机密钥库已验收。

本轮仅 Linux 本地测试；真实七牛/OSS/坚果云账号、GUI 帧率、系统密钥库及安装包尚未验证。正式发布前应带真实账号做最小库联调和大库验收。Python 兼容后端暂不提供云同步入口。
