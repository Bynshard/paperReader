# Moonlight 前端视觉审美与交互体验（UI/UX）深度审查与重构指南

> **适用代码基线**：`paperReader/app/src/*`（React 18 + TanStack Table/Virtual + PDF.js + `styles.css`）  
> **文档目标**：针对当前桌面端“工程原型感重、视觉陈旧杂乱、交互反直觉”的问题，提供可直接交给前端工程师逐项落地的 UI/UX 重构规范。

---

## 一、 总体诊断：为什么现在的界面“看着不舒服、用着别扭”？

当前前端代码虽然跑通了功能，但在视觉设计和交互架构上存在 **4 个系统性问题**：

1. **布局空间分配失衡**：进入 PDF 阅读器后，左侧 236px 的论文库导航栏依然常驻且点击无效（假死状态），加上右侧 360px 边栏，直接吃掉近 600px 宽度，导致双栏对照阅读区域被严重挤压。
2. **多代工具栏与工程状态裸露堆叠**：论文库顶部叠了 3 层工具条，阅读器顶部叠了“导航栏 + 文档解析/OCR 工具条 + 翻译任务条”，把原本属于后台自动处理的工程概念（如“解析当前页”、“查看将发送的上下文 Prompt”）全部做成按钮摊在用户脸上。
3. **视觉语言陈旧、缺乏统一组件规范**：
   - 全屏使用 7 种明度接近的米黄/灰黄色（`#f3f0e9` / `#fbf9f4` / `#ebe6db` / `#e7e2d6`）配实线边框，显得灰暗、陈旧；
   - **零矢量图标**，全靠 `◐`、`◫`、`★`、`▾`、`⋯`、`‹` 等原生字符硬凑，不同系统字体下基线错位；
   - 部分弹窗（如 `PaperEditor.tsx`）甚至漏写输入框样式，直接裸露出浏览器默认的 Windows 95 风格原生 `<input>` 和 `<select multiple>`。
4. **核心交互违背直觉**：比如表格里点第 20 行的 `⋯` 菜单，弹窗却出现在表格右上角；PDF 选词后没有就地浮动菜单，反而强制把右侧 AI 面板跳回“笔记”Tab；单击论文标题直接进阅读器，没有右侧详情预览抽屉。

## 二、 必改的硬伤级交互与定位 Bug（P0）

### 1. 进入阅读器时，左侧全局导航栏常驻且“点击假死”
- **代码位置**：`app/src/App.tsx`（第 209–288 行）
- **现状问题**：
  - `<aside className="sidebar">`（固定 `236px`）在 `openPaper` 打开阅读器时依然占据左侧空间；
  - 更严重的是，阅读器打开时点击左侧“全部论文 / 星标 / 未读 / 目录 / 标签”，只会修改后台的 `filter` 状态，**不会关闭 `openPaper` 返回列表**，用户点了没有任何反应；
  - 在 1440px 窗口下开启“原文+译文”双栏对照时，左右边栏共占去 `236 + 360 = 596px`，每页 PDF 只剩 `420px` 宽度，正文字体极小。
- **修改方案**：
  - **方案 A（推荐，类 Zotero 7 / Readwise）**：顶层采用多标签页（Tabs）或阅读模式自动折叠左侧栏（提供左上角汉堡按钮 `☰` 或快捷键 `Ctrl+\` 呼出浮动抽屉）；如果在侧栏点击了任何分类/标签，自动切换回论文库列表视图。
  - **方案 B**：右侧边栏（AI/笔记）与左侧边栏均支持拖拽调节宽度（Resizable Pane）和一键收起。

### 2. 左下角“任务中心”按钮悬浮错位，直接遮挡侧边栏内容
- **代码位置**：`app/src/App.tsx`（第 290 行）、`app/src/styles.css`（第 238 行）
- **现状问题**：
  ```css
  .task-center-button { position: fixed; left: 12px; bottom: 72px; z-index: 30; }
  ```
  一个普通按钮用 `position: fixed` 硬贴在左下角 `bottom: 72px` 处，悬空盖在左侧目录树/标签云之上，极其突兀。
- **修改方案**：
  - 移除 `position: fixed`；
  - 将“任务中心”与“设置与状态”并排收纳进左侧边栏底部的 `.sidebar-foot` 固定槽位中，并显示当前运行中任务的徽标数字（Badge）或旋转进度图标。

### 3. 表格视图中“更多操作 `⋯`”菜单定位完全错误
- **代码位置**：`app/src/PaperTable.tsx`（第 38、57 行）、`app/src/styles.css`（第 329 行）
- **现状问题**：
  ```css
  .table-context-menu { position: absolute; top: 42px; right: 10px; z-index: 35; }
  ```
  用户在表格任意一行点击右侧 `⋯` 按钮，弹出的操作菜单**不会出现在按钮旁边，而是永远固定在整张表格的右上角（`top: 42px; right: 10px`）**！且点击外部区域无法关闭菜单，必须点菜单内的“关闭”。
- **修改方案**：
  - 改为基于触发按钮 `getBoundingClientRect()` 的 Portal 浮动定位菜单（Popover），并支持整行右键触发（`onContextMenu`）；
  - 监听全局 `pointerdown` 与 `Escape` 键实现点击外部自动关闭。

### 4. “编辑论文资料”弹窗漏写表单样式 + 反人类的 `<select multiple>`
- **代码位置**：`app/src/PaperEditor.tsx`（第 12–23 行）、`app/src/styles.css`（第 234–236 行）
- **现状问题**：
  - `.paper-editor input, .paper-editor textarea, .paper-editor select` 只设置了 `width: 100%`，**没有设置 `padding`、`border`、`border-radius`、`background`**，导致渲染出极其简陋的浏览器原生输入框；
  - 分类选择使用了原生 `<select multiple>`，用户如果不按住 `Ctrl/Cmd` 点击，会瞬间清空已选的所有其他分类；
  - 10 个字段单列垂直排布，弹窗过长。
- **修改方案**：
  - 提炼全局统一的表单样式类（统一 `border: 1px solid var(--border)`、`border-radius: 8px`、`padding: 8px 10px`、聚焦高亮态）；
  - 将年份、期刊/会议、DOI、arXiv、阅读状态改为 **2 列网格布局（Grid）**；
  - 将分类和标签选择器改为 **多选胶囊复选框（Checkbox Pills / Combobox）**，废除原生 `<select multiple>`。

## 三、 论文库页面（Library）视觉与交互重构（P1）

### 1. 消除“三层工具栏堆叠”与满屏说明书文字
- **代码位置**：`app/src/Library.tsx`（第 54–77 行）、`app/src/PaperTable.tsx`（第 51–52 行）
- **现状问题**：
  目前列表上方垂直堆了三排工具条：
  1. `.library-head`（标题 + 视图切换 + 搜索 + 排序 + Zotero 导入 + 导入 PDF）
  2. `.library-organize-bar`（全选 + 已选 N 篇 + 分类/标签 + 更新引用量 + 灰色说明文字）
  3. `.table-view-tools`（列表预设下拉 + 显示列按钮 + 第二行灰色说明文字）
  界面显得非常拥挤、琐碎，且无论有没有选中论文，批量操作栏都一直占位。
- **修改方案**：
  - **合并顶部工具栏为单行紧凑 Header**：左侧放当前视图标题与篇数徽标，中间放带快捷键提示（`Ctrl+K / /`）的搜索框，右侧放 `[导入 PDF ▾]`（下拉整合“本地 PDF”、“从 Zotero 导入”、“通过 DOI/arXiv 导入”）、视图切换图标按钮、列设置图标按钮。
  - **采用上下文浮动批量操作栏（Contextual Action Bar）**：当 `selected.size === 0` 时，隐藏批量操作栏；当勾选论文（`selected.size > 0`）时，在列表底部中央或表头位置平滑浮现操作胶囊：`已选 N 篇 | 分类/标签 | 更新引用量 | 导出 BibTeX | 移入回收站 | 取消选择`。
  - **删除冗余的说明文案**：去掉“左侧可新建分层目录…”、“拖动表头边缘调整列宽…”等占位提示。

### 2. 区分“单击预览详情”与“双击进入阅读器”
- **代码位置**：`app/src/Library.tsx`（第 99–104 行）、`app/src/PaperTable.tsx`（第 31、55 行）
- **现状问题**：
  当前单击论文标题直接离开列表进入全屏 PDF 阅读器，同时外层又绑了 `onDoubleClick` 打开阅读器。用户在整理文献时，如果只想看一眼某篇论文的摘要、完整作者、DOI 或笔记，必须点进 PDF 阅读器或打开编辑弹窗，非常低效。
- **修改方案**：
  - **单击行**：高亮选中当前行，在右侧滑出 `320px` 宽的**论文详情检视面板（Inspector Drawer）**，直接展示并允许就地编辑：标题、作者、年份/会议、DOI/arXiv 外链、一句话速记、摘要、标签、笔记、附件版本列表及 `[打开阅读]` 主按钮；
  - **双击行**或点击 `[阅读]` 按钮：进入 PDF 阅读器。

### 3. 阅读状态应支持列表内一键流转
- **代码位置**：`app/src/PaperTable.tsx`（第 37 行）
- **现状问题**：表格里的“未读 / 在读 / 已读”只是一个静态 `<span>` 标签，想改状态必须点开 `⋯ -> 编辑资料` 弹窗。
- **修改方案**：将 `.reading-state` 胶囊改为可点击的轻量下拉或循环切换按钮，一键在 `未读 → 在读 → 已读` 间切换。

## 四、 阅读器（Reader）与 AI 助手视觉与交互重构（P1）

### 1. PDF 选词交互：用“就地浮动菜单”替代“强制切 Tab”
- **代码位置**：`app/src/Reader.tsx`（第 418–422、444–447、466–490 行）
- **现状问题**：
  用户在 PDF 上划选一段文字后，PDF 页面上没有任何操作入口；代码执行 `if (s) setTab("notes")`，强行把右侧边栏从“AI 阅读助手”切到“笔记”面板，让用户去右侧面板顶部点“黄色高亮 / 绿色高亮 / 翻译 / 解释”。这导致视线来回横跨整个屏幕，且打断正在进行的 AI 提问。
- **修改方案**：
  - **删掉 `if (s) setTab("notes")`**；
  - 当选中文本后，在选区上方/下方 `8px` 处弹出紧凑的 **浮动工具栏（Selection Popover）**：
    `[🟡] [🟢] [🔵] [🔴] | [📝 批注] [🌐 翻译] [✨ 解释] [💬 引用提问] [📋 复制]`
  - 点击颜色圆点直接完成高亮（无需跳去右边栏）；点击“批注”才展开小输入框写评论；点击“翻译/解释/引用提问”自动联动右侧 AI 面板。
  - **支持页面内高亮块直接交互**：将 `.highlightLayer` 中的 `.highlight` 元素设为 `pointer-events: auto; cursor: pointer;`，点击已有高亮时弹出小气泡展示评论、修改颜色或删除。

### 2. 收纳“文档解析 / OCR”工具条，还阅读器干净顶部
- **代码位置**：`app/src/Reader.tsx`（第 387 行）、`app/src/DocumentParsing.tsx`
- **现状问题**：
  阅读器顶部栏下方永远横着一条 `.document-parsing` 工具栏（展示 `正文索引：x/y 页` 和 3 个按钮：`解析当前页`、`OCR 当前页`、`解析全文`）。对于 95% 的原生文本 PDF，进入页面时 PDF.js 已经自动提取文本，这条工具栏完全是视觉噪音。
- **修改方案**：
  - 将索引状态浓缩为阅读器顶部栏的一个轻量状态胶囊（例如 `✓ 已索引` 或 `⚠ 扫描件 · 点击 OCR`）；
  - 仅当检测到当前页无原生文本层（扫描页）时，才在页面顶部给出温和的提示条：“检测到当前页为扫描图像，[一键运行离线 OCR]”；常规解析选项收进顶部更多菜单。

### 3. 重构 AI 阅读助手：从“调试表单”升级为“现代对话流（Chat UI）”
- **代码位置**：`app/src/Reader.tsx`（第 517–574 行）
- **现状问题**：
  当前的 AI 面板把低频配置项放在最顶部（上下文范围下拉框、带入 6 轮历史复选框、“查看将发送的上下文”按钮及大文本框），中间是提问框，下面只显示**最后一次回答**，历史记录被塞进 `<details><summary>对话历史</summary>` 折叠列表里。整体像一个后端接口调试器。
- **修改方案**：
  - **标准三段式 Chat 布局**：
    1. **顶部快捷动作栏（固定）**：`[📄 总结本页]`、`[🔍 提炼核心贡献]`、`[⚙️ 上下文设置（Popover 收纳范围与预览）]`；
    2. **中部对话消息流（`flex: 1; overflow-y: auto`）**：按时间顺序展示用户提问气泡与 AI 回答卡片（包含 Markdown 渲染、可点击的 `[1] p.4` 胶囊引用角标、一键复制/存入笔记按钮）；
    3. **底部固定输入区（Sticky Bottom）**：上方显示当前选区引用预览条（如有选区），下方为自适应高度输入框 + 右下角发送/停止按钮（支持 `Enter` 发送、`Shift+Enter` 换行）。

### 4. 补齐阅读器左侧大纲目录（Outline）与缩放控制
- **代码位置**：`app/src/Reader.tsx`（第 336–363 行）、`app/src/PdfPane.tsx`
- **修改方案**：
  - 在阅读器左上角提供 `[📑 目录大纲 / 缩略图]` 切换按钮，展开窄侧栏显示 PDF 章节书签（调用 `doc.getOutline()`）；
  - 缩放控件增加 **`[适应页宽]`**、**`[100%]`** 预设下拉，并支持按住 `Ctrl/Cmd + 鼠标滚轮` 缩放；
  - 增加阅读器内搜索快捷键 `Ctrl+F` 浮动查找条。

## 五、 设置中心与全局视觉设计系统重构规范（P1）

### 1. 拆分“大杂烩设置弹窗”为左右分栏 Tab 结构
- **代码位置**：`app/src/App.tsx`（第 366–393 行）
- **现状问题**：当前“设置与状态”Modal（宽 `520px`）把系统信息、翻译 API、备份恢复、Codex 登录、云同步 5 大块内容垂直拼在一个滚动条里，信息密度极高且容易误操作。
- **修改方案**：
  - 将设置弹窗拓宽至 `760px × 560px`，采用**左侧二级导航（180px）+ 右侧内容面板**结构：
    - `通用与论文库`（版本、库路径、离线状态）
    - `翻译引擎 (BabelDOC)`（API 地址、Key、模型、测试连接按钮、即时生效无需重启）
    - `AI 阅读助手 (Codex / API)`（服务切换、账号登录、额度进度条）
    - `云同步 (WebDAV / S3)`（配置、同步状态、冲突解决）
    - `备份与恢复`（创建备份、从备份恢复）

### 2. 升级色彩体系与图标系统（Design Tokens）
- **代码位置**：`app/src/styles.css`（第 1–26 行）
- **问题与改进建议**：
  - **引入 `lucide-react` 图标库**：彻底替换掉代码中的 `◐`、`◫`、`★`、`▾`、`⋯`、`＋` 等字符，统一使用 `16px / 18px`、`stroke-width: 1.75` 的现代线性图标。
  - **优化配色层次（保留温和护眼调性，但告别浑浊感）**：
    | 变量名 | 现值（偏黄偏暗） | 建议新值（清爽暖白/森系绿） | 用途说明 |
    | :--- | :--- | :--- | :--- |
    | `--bg` | `#f3f0e9` | `#f7f6f2` | 全局底层背景（降低黄度，更干净） |
    | `--sidebar` | `#ebe6db` | `#f0eee8` | 侧边栏背景，与主内容区自然区分 |
    | `--panel` | `#fbf9f4` | `#ffffff` | 表格、卡片、侧栏面板采用纯白或极浅暖白，提升文字对比度 |
    | `--reader-bg`| `#e7e2d6` | `#e4e2dc` | PDF 画布衬底，突出白色 PDF 页面阴影 |
    | `--line` | `#e2ddd2` | `#e6e4dd` | 弱化分割线对比度，减少网格割裂感 |
    | `--accent` | `#2e6b5a` | `#256353` | 主强调色（深松绿），提高饱和度与可读性 |
    | `--ink` | `#22252a` | `#181a1f` | 主文本色，加深对比度 |

## 六、 前端开发人员执行清单（Checklist）

前端同学可按以下顺序逐步提交 PR：

- [ ] **Step 1（修 Bug 与基础样式）**：引入 `lucide-react`；补齐 `.paper-editor` 等缺失的全局表单 `input/select/textarea` 样式；修复 `PaperTable.tsx` 的 `.table-context-menu` 行级浮动定位与外部点击关闭；将左下角悬浮的 `.task-center-button` 移入 `.sidebar-foot`。
- [ ] **Step 2（修布局与导航）**：在打开 `Reader` 时自动折叠左侧 `.sidebar`（或点击左侧导航时自动退回列表视图），并支持右侧 `.side` 面板拖拽宽度与收起。
- [ ] **Step 3（升级论文库交互）**：合并 `Library.tsx` 三层工具栏，改为选中论文后才出现浮动批量操作栏；实现“单击行右侧滑出论文详情抽屉（Inspector），双击行打开阅读器”；支持表格内一键点击切换“未读/在读/已读”。
- [ ] **Step 4（升级阅读器与 AI 面板）**：去掉选词强制切 `notes` Tab 的逻辑，实现 PDF 选区旁浮动工具条（Popover）；开启 `.highlight` 点击编辑/删除气泡；将 AI 面板重构为底部输入框 + 中部流式对话气泡列表；将 `DocumentParsing` 收纳为顶部状态胶囊。
- [ ] **Step 5（重构设置弹窗）**：将 `showSettings` 弹窗重构为左侧 Tab 导航（通用 / 翻译 / AI / 云同步 / 备份）+ 右侧内容区的分栏布局，并将分类/标签编辑升级为多选胶囊组件。
